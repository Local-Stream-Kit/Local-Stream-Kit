The markup and its classes

The look is your CSS: it styles this markup. Each message is a .msg in .chat, newest last:

.chat
  .msg …classes
    .msg__reply
      .msg__reply-name  .msg__reply-text
    .msg__head
      .msg__badges > img.badge.badge--<set>
      .msg__name
    .msg__body
      text, span.emote > img.emote__image
                         (+ img.emote__overlay)
      span.text-style.text-style-<name>  (a part a card's text marked)

.msg__head is left out when a line has no name, .msg__badges when it has no badges, .msg__reply unless it's a reply (and "Show the message a reply answers" is on). The name's colour is var(--name-color).

Classes on .msg, each when it applies:

  • .msg--chat a viewer's message
  • .msg--card from a card's Show in chat node, with the node's class
  • .msg--from-twitch the platform it came from
  • .msg--single-emote one emote and nothing else
  • .msg--emotes-only two or more emotes and nothing else
  • .msg--text any text, with or without emotes
  • .msg--broadcaster .msg--moderator .msg--vip .msg--member who wrote it
  • .msg--action a /me message
  • .msg--highlighted paid to be highlighted
  • .msg--first the viewer's first message in the channel
  • .msg--reward sent with a channel point reward
  • .msg--cheer came with bits
  • .msg--reply answers another message (.msg__reply shows which, unless that's turned off)
  • .msg--restored shown again after the Browser Source reloaded, so CSS can skip its entrance
  • .msg--leaving on its way out; it's removed when its animation or transition ends

A Show in chat node's text can mark parts with a text style (Plugins → Text styles), [highlight]{viewer}[/]: the part is in a span.text-style.text-style-highlight with the style's font, size and colour inline, which your CSS can add to or override.

Fonts can come from Google Fonts (@import url("https://fonts.googleapis.com/css2?…")).
